Copysight API

IP detection for images and video — logos, characters, celebrities, brand designs, artwork.

Basics

Base URLhttps://api.copysight.ai
AuthHeader x-api-key: cs_live_… on every request
MediaJPEG, PNG, WebP, GIF · video MP4, MOV, WebM, MKV and other common containers

Scoring modes

  • Basic (default) — each detection carries a similarity score 0–1.
  • Advanced (advanced=true) — higher-accuracy mode. Same response format; similarity values are more discriminative.
POST/v1/verify

Synchronous analysis. Waits and returns the result. Best for images and short videos. (POST / is equivalent.)

FieldDescription
fileMedia bytes (multipart). Provide either file or url.
urlhttp(s) media URL, e.g. a pre-signed S3 link (≤ 200 MB). Also accepted as ?url= or JSON body {"url": …}.
advancedtrue — advanced scoring mode (see Scoring modes).
face_detection_threshold0–1. Drops Celebrities and famous people detections with similarity below the value. Other categories unaffected.
scene_change_sensitivityVideo only, 0–1 (default 0.15). Frame-difference cutoff for which frames get analyzed; lower = more frames analyzed. (sensitivity is a deprecated alias.)
curl -X POST "https://api.copysight.ai/v1/verify" -H "x-api-key: $KEY" \
  -F "file=@image.jpg" -F "advanced=true" -F "face_detection_threshold=0.5"

POST/v1/jobs

Asynchronous analysis. Returns immediately with a job id; fetch results by polling and/or webhook. Use for large files and videos.

FieldDescription
fileMultipart upload, < ~30 MB. Exactly one of file / url / gcs_uri.
urlhttp(s) media URL (pre-signed S3 etc.). Sign for plain GET; keep valid ≥ 1 hour; pass verbatim — don't re-encode.
gcs_uriFrom POST /v1/uploads — for files of any size.
webhook_urlOptional. HTTPS endpoint POSTed the result on completion.
webhook_secretOptional. HMAC key for webhook signatures.
advanced, face_detection_threshold, scene_change_sensitivitySame as the sync endpoint.
→ 202  {"job_id": "d4dd…", "status": "queued", "status_url": "/v1/jobs/d4dd…"}

Fields accepted as form data or JSON.

GET/v1/jobs/{job_id}

Job status and result. Visible only to the API key that created the job.

{
  "job_id": "d4dd…",
  "status": "queued" | "processing" | "succeeded" | "failed",
  "created_at": "…", "started_at": "…", "finished_at": "…",   // ISO 8601
  "credits_charged": 31,
  "result": { … },        // when succeeded — same shape as sync responses
  "error": "…",           // when failed
  "webhook": {"url": "…", "delivered": true, "last_status": 200, "attempts": 1}
}                          // webhook block present only if one was configured
POST/v1/uploads

Upload session for large files (no size limit). Bytes go directly to storage, not through the API.

curl -X POST "https://api.copysight.ai/v1/uploads" -H "x-api-key: $KEY" \
  -H "Content-Type: application/json" \
  -d '{"filename": "movie.mp4", "content_type": "video/mp4"}'
→ 201 {"upload_url": "https://storage.googleapis.com/…", "gcs_uri": "gs://…"}

curl -X PUT --upload-file movie.mp4 "$UPLOAD_URL"    # no auth header needed
# then create a job with {"gcs_uri": …}

The session is single-use and valid for 24 hours — complete the upload and create the job within that window. Chunked resumable uploads are supported.

Webhooks

When a job reaches succeeded or failed, its full status payload (identical to GET /v1/jobs/{id}) is POSTed to your webhook_url. 3 attempts with backoff, 15 s timeout each; delivery state is recorded on the job. Treat webhooks as a notification — polling always works.

If you set webhook_secret, verify each delivery:

X-Copysight-Signature: sha256=<hex>

# HMAC-SHA256 of the RAW request body, keyed with your secret:
expected = "sha256=" + hmac.new(secret, raw_body, hashlib.sha256).hexdigest()
valid = hmac.compare_digest(header, expected)   # constant-time compare

Respond 2xx quickly (enqueue, process later) and be idempotent on job_id — a slow response can cause a duplicate delivery.

Errors

StatusMeaning
400Malformed request — missing/conflicting media source, invalid URL.
401Missing, unknown, or revoked API key.
402Insufficient credits.
404Unknown job, or a job owned by another key.
413URL payload exceeds the size cap.
422Media could not be processed (corrupt / unsupported file).
429API key credit limit exceeded.
500 / 503Server error / transient dependency failure — retry with backoff.

Error bodies are JSON {"error": "…"} where applicable. Unknown response fields may be added at any time — ignore what you don't recognize.
