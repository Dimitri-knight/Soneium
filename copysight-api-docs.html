API Documentation

Your guide to integrating with the CopySight API.

Base URL

All API requests should be made to the following base URL:

https://api.copysight.ai/v1

All requests must be made over HTTPS.

Authentication

Authentication is by API key, sent as a request header on every call.

KeyDescription
X-API-KeyYour unique API key for authentication.

Keep your key server-side. An API key authorizes analysis on your account. Do not embed it in browser code, mobile apps, or anything distributed to end users — call the API from your own backend instead.

Quick start

# analyze an image file
curl -X POST "https://api.copysight.ai/v1/verify" \
  -H "X-API-Key: $COPYSIGHT_API_KEY" \
  -F "file=@artwork.png"

# analyze from a URL, with advanced detection
curl -X POST "https://api.copysight.ai/v1/verify" \
  -H "X-API-Key: $COPYSIGHT_API_KEY" \
  -F "url=https://example-bucket.s3.amazonaws.com/artwork.png?X-Amz-Signature=…" \
  -F "advanced=true"

# analyze a video
curl -X POST "https://api.copysight.ai/v1/verify" \
  -H "X-API-Key: $COPYSIGHT_API_KEY" \
  -F "file=@spot.mp4" \
  -F "sensitivity=0.10"

Endpoints

POST/verify

Analyzes an image or video to detect intellectual property and returns a list of findings.

Headers

KeyDescription
X-API-KeyYour unique API key for authentication.
Content-Typemultipart/form-data for uploads and for any request that sets options. application/json is accepted when submitting a URL only.

Request Body

Send a multipart/form-data payload. Provide the media either as a file upload or as a url — one media item per request.

FieldTypeDefaultDescription
fileconditionalFile— The image or video to analyze. Required unless url is provided. Takes precedence if both are sent.
urlconditionalString— A publicly reachable or pre-signed http(s) URL to the media. Required unless file is provided. The URL must grant access on its own — no credentials are sent with the fetch.
advancedBooleanfalse Enables advanced detection. Accepts true, 1 or yes. See Advanced detection.
sensitivityNumber0.15 Video only. Threshold from 0 to 1 controlling how many frames are analyzed. See Video sensitivity. Ignored for images.

Options must be sent as form fields. advanced and sensitivity are read from the multipart/form-data body. They are not read from the query string or from a JSON body — a request that sends the URL as ?url= or as JSON runs with the defaults. If you need either option, send the request as multipart with url as a form field.

Supported media

TypeFormatsNotes
ImageJPEG, PNG, WebP, GIFReturns the image response schema.
VideoMP4, MOV, WebM, AVI, MKV, M4V, MPEG, MPG, 3GP Detected from the content type or file extension. Returns the video response schema.

Maximum media size is 200 MB when submitting a url, and 32 MB for a direct file upload — use a URL for anything larger. The endpoint fetches a submitted URL for up to 120 seconds and identifies itself as CopysightBot/1.0; allow that agent if your origin filters by user agent.

Successful Response (200 OK)

For an image, a JSON object containing a contains_face boolean and a detected_ips array of detected intellectual property objects.

{
  "contains_face": false,
  "detected_ips": [
    {
      "name": "Mickey Mouse",
      "category": "Characters",
      "author": "Walt Disney and Ub Iwerks",
      "owner": "The Walt Disney Company",
      "bounding_box": {
        "x": 0.277,
        "y": 0.469,
        "width": 0.021,
        "height": 0.022
      },
      "similarity": 0.98
    }
  ]
}

An empty detected_ips array means no intellectual property was detected.

Response Object Schema

FieldTypeDescription
contains_faceBooleanWhether the image contains a human face.
detected_ipsArrayList of detected intellectual property objects. Each item contains the fields below.
nameStringName of the intellectual property.
categoryStringCategory of the IP. Can be Trademarks, Brand and iconic designs, Characters, Celebrities and famous people, Art and artists.
authorStringOriginal creator of the intellectual property. Returns "N/A" when not applicable or unknown.
ownerStringCurrent owner or rights holder of the intellectual property. Returns "N/A" when not applicable or unknown.
bounding_boxObjectNormalized coordinates and dimensions of the detected IP (values from 0 to 1): {"x": number, "y": number, "width": number, "height": number}. x and y are the top-left corner; multiply by the image's pixel width and height to draw the box.
similarityNumberThe confidence/similarity score of the detection (0-1).

Video Response (200 OK)

Video returns a different shape. Instead of an array, detected_ips is an object keyed by IP name, and each entry lists the timecodes where that IP appears. The presence of media_type tells you which shape you received.

{
  "media_type": "video",
  "frames_analyzed": 12,
  "duration_seconds": 27.4,
  "contains_face": true,
  "detected_ips": {
    "Mickey Mouse": {
      "category": "Characters",
      "author": "Walt Disney and Ub Iwerks",
      "owner": "The Walt Disney Company",
      "max_similarity": 0.98,
      "occurrence_count": 2,
      "occurrences": [
        {
          "timecode": 4.0,
          "timecode_label": "0:04",
          "similarity": 0.91,
          "bounding_box": { "x": 0.10, "y": 0.20, "width": 0.22, "height": 0.14 }
        },
        {
          "timecode": 19.0,
          "timecode_label": "0:19",
          "similarity": 0.98,
          "bounding_box": { "x": 0.55, "y": 0.31, "width": 0.19, "height": 0.12 }
        }
      ]
    }
  }
}

Video Response Schema

FieldTypeDescription
media_typeStringAlways "video". Present only on video responses — use it to tell the two shapes apart.
frames_analyzedNumberHow many frames were analyzed.
duration_secondsNumberTimecode of the last analyzed frame, in seconds.
contains_faceBooleanWhether any analyzed frame contains a human face.
detected_ipsObjectMap keyed by IP name. Each value contains the fields below.
categoryStringCategory of the IP, from the same list as the image schema.
authorStringOriginal creator of the intellectual property.
ownerStringCurrent owner or rights holder.
max_similarityNumberHighest similarity score across all occurrences (0-1).
occurrence_countNumberHow many analyzed frames the IP appeared in.
occurrencesArrayChronological list of appearances. Each item contains the fields below.
timecodeNumberSeconds from the start of the video.
timecode_labelStringThe same timecode formatted as M:SS.
similarityNumberConfidence score for that frame (0-1).
bounding_boxObjectNormalized position of the IP within that frame, same shape as the image schema.

Advanced detection

Setting advanced=true switches to a precision-oriented detector. The response schema is unchanged — only which detections are returned, and how they are named.

BehaviourDefaultadvanced=true
Optimized forCoverage — returns all plausible matchesPrecision — withholds matches it cannot assert confidently
People and public figuresReturned like any other matchReturned only on unambiguous facial evidence. Synthetic or AI-generated faces are not identified as real individuals.
name valuesDescriptive, may include qualifiers — "Nike Logo and Swoosh Design"Canonical short form, stable across requests — "Nike Logo". Safe to use as a lookup key.
Generic elementsPoses, garments and common motifs may appearNot returned
Low-confidence matchesReturned with a low similarityReturned in the 0.5–0.7 range, or withheld
Response schemaIdentical in both modes

Use the default for broad sweeps and triage where a human reviews the output. Use advanced=true for clearance checks, automated gates, and results shown to a customer or counterparty.

The same input generally returns fewer detections with advanced=true. That is the mode working as intended, not an error — do not treat a lower count as a failed request.

For video, advanced applies to every analyzed frame.

Video sensitivity

Videos are not analyzed frame by frame. Frames are sampled along the timeline and analyzed only when they differ visually from the previously analyzed frame by more than sensitivity, up to a maximum of 50 frames per video. The first frame is always analyzed.

ValueEffectGood for
0.05–0.10Analyzes more frames; catches brief appearancesFast-cut edits, short-form ads, evidence capture
0.15Default balanceGeneral content
0.25–0.40Analyzes scene changes onlyLong-form, static or single-shot footage

Because selection is driven by visual change rather than length, a long static clip may yield a single frame while a short rapid-cut clip may reach the 50-frame maximum. Read frames_analyzed on the response to see the coverage you actually got. If you need a specific moment covered exactly, extract that frame yourself and submit it as an image.

A value that cannot be parsed as a number falls back to the default without an error.

Error Responses

When an error occurs, the API returns an appropriate HTTP status code along with a JSON error response. Branch on the status code rather than on the message text, which may change.

401

Unauthorized

Invalid or missing API key. Ensure your X-API-Key header is correct.

{
  "error": "Unauthorized",
  "message": "Invalid API key"
}
400

Bad Request

No media supplied, an unsupported URL scheme, a URL that could not be fetched, or an invalid or corrupted file.

{
  "error": "Bad Request",
  "message": "Unsupported file format or corrupted file"
}
413

Payload Too Large

The media exceeds the size limit for the submission method. Submit large media by url rather than as an upload.

422

Unprocessable Entity

The media was accepted but could not be analyzed — an image that failed to decode, a video whose container or codec could not be read, or a video from which no analyzable frames could be selected. Re-encoding to H.264 MP4, or lowering sensitivity, resolves most cases.

429

Too Many Requests

Rate limit exceeded. Please wait before making another request.

{
  "error": "Too Many Requests",
  "message": "Rate limit exceeded. Try again later.",
  "retry_after": 60
}

Honour retry_after, in seconds, when it is present.

500

Internal Server Error

An unexpected error occurred. Safe to retry once.

503

Service Unavailable

Temporary capacity issue. Retry with exponential backoff.

Retry summary

StatusRetry
400, 413, 422No — fix the request or the media first
401No — check the key
429Yes, after retry_after
500Once
503Yes, with exponential backoff and jitter

Implementation notes

  • Check media_type before parsing. detected_ips is an array for images and an object for video. This is the single most common integration bug.
  • One media item per request. If both file and url are sent, file wins.
  • Set a generous timeout. Video analysis scales with the number of frames and can take several minutes. Run it asynchronously rather than inside a synchronous user request.
  • Requests are not idempotent. Retries re-run the request; build retry logic accordingly.
  • Identical media returns identical results. Resubmitting the exact same bytes in the same mode returns the same response, quickly. Re-encoded or resized media is treated as new.
  • Apply your own threshold. similarity is a confidence signal, not a verdict. Pick a cutoff that suits your workflow — for example auto-flag above 0.9 and queue 0.6–0.9 for review.
  • Store the full response. Bounding boxes and timecodes are what make a detection reviewable later.
  • Detection is not a legal determination. The API reports detected intellectual property and the evidence for it. It does not assess infringement, fair use, or licensing status.

Questions or a problem with an integration: hello@copysight.ai. Include the request timestamp, the response status, and the first 8 characters of your key — never the full key.
